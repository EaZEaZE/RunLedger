# RunLedger 双产品演示视频脚本

> 本文件是**录制脚本，不是视频成片**。画面中的操作必须在真实运行的 `/life`、`/lab` 页面上完成；数字、诊断和导出结果以录制时界面为准。若操作失败，保留失败并解释，不切换成预造成功画面。
>
> 与 `video-script.md` 的分工：那份是比赛要求的 5–8 分钟主片（含真实 AI 协同）；本文件是**两个产品的独立演示片**，用于作品展示、社交传播和评审快速理解。

## 通用录制规范

- 演示前运行 `npm.cmd run typecheck` 与 `npm.cmd run build`，用生产模式或稳定开发模式录制。
- 使用无痕窗口或全新浏览器配置，避免出现私人记录、书签、账号和通知。
- 不打开 `.env.local`，不展示任何密钥；AI 未配置时只展示真实的 `503 AI_NOT_CONFIGURED` 回退。
- 所有界面文字以实际 UI 为准；本脚本中的按钮名按当前版本编写（新建、CSV模板、导入记录、导出报告、导出证据JSON、下载CSV模板、或逐条录入）。
- 录制中如修改数据，只使用明确标注为“演示测试值”的临时记录，不冒充真实长期生活数据。
- 结尾必须出现边界声明；不得宣称显著、有效、因果或健康收益。

## A. RunLedger Life · 60 秒竖屏（9:16）

| 时间 | 画面与操作 | 屏幕字幕 | 口播 |
| --- | --- | --- | --- |

| 04–12 | 总览页，鼠标停在标题与两条件均值上 | 感觉到了 ≠ 查过了 | 感觉会被记忆放大。想认真回答，需要两种条件下的真实记录。 |
| 12–24 | 依次切换两个内置实验；展示 64 条 / 32 对、36 条 / 18 对 | 64 条 / 32 对 · 36 条 / 18 对 | 这里的内置演示来自 CC0 公开数据，每条是一位参与者在一种条件下的日均值，不是把重复日期当成独立的人。 |

## B. RunLedger Life · 3 分钟横屏（16:9）

**目标**：完整走一遍“建实验 → 录数据 → 看诊断 → 导出证据”，适合作品页或评审观看。

### 00:00–00:20 开场与定位

- **画面**：`/` 选择页，鼠标从 Life 卡片移入；进入 `/life` 总览。
- **口播**：“RunLedger Life 是一个个人生活决策记录工具。它只做一件事：把你对生活的两种假设，变成可以复查的数值对照。”

### 00:20–00:50 内置演示：先看两份真实聚合数据

- **操作**：停留在“周末会走得更多吗？”，指出两条件均值；切到“睡得更久后，第二天会走更多吗？”。
- **字幕**：64 条 / 32 对；36 条 / 18 对。
- **口播**：“两份演示都来自 CC0 的 Fitbit 公开数据，先按参与者聚合为条件日均值。均值只描述当前样本，不能单独证明条件导致变化。”

### 00:50–01:35 新建一个自己的生活实验

- **操作**：点击「新建」→ 填写两个条件（如“通勤走路 / 通勤骑车”）、指标“单程耗时”、单位“分钟”、目标方向“越低越好”、目标记录数 10；勾选“使用配对编号”（或按实际设计不勾）。提交。
- **字幕**：两种条件 + 一个数值指标。
- **口播**：“新建时先固定条件和指标。目标方向决定后面差异怎么判读；是否配对取决于你的记录是否成对出现，不确定就不要勾。”

### 01:35–02:20 录入真实记录

- **操作**：点击「CSV模板」下载，打开模板展示 `config_id`、`value`、`repeat` 三列；说明空白不能导入。返回页面用「或逐条录入」现场录入 2–4 条**演示测试值**。
- **字幕**：模板空值不能直接导入。
- **口播**：“系统不会为空白实验生成示例结果。可以逐条录，也可以下载模板批量导入；导入只会追加新批次，不覆盖原始记录。”

### 02:20–02:50 诊断与复测优先级

- **操作**：切到「对比诊断」，选一条诊断展开证据；再切「复测计划」查看排序。
- **字幕**：信号噪声比只用于排序，不是 p 值。
- **口播**：“它会直接说清问题：样本不够、差异落在波动里，还是两组完全一样。复测计划按缺口排序，而不是让你盲目多记。”

### 02:50–03:00 导出与边界

- **操作**：进入「记录与证据」，点击「导出证据JSON」，再回顶部「导出报告」；最后停在边界文字。
- **口播**：“记录可导出为证据 JSON 和 HTML 报告。观察关联不等于因果，它不做医疗诊断，也不承诺健康效果。”

**目标**：让工程观众快速理解“它和随便跑一次 benchmark 有什么不同”。

| 时间 | 画面与操作 | 屏幕字幕 | 口播 |
| --- | --- | --- | --- |
| 00–04 | 黑底白字开场，切到 `/lab` 总览 | 这次，真的更快吗？ | 改完代码，跑一次，快了。然后呢？ |
| 04–12 | 展示 digits 两配置均值 | 93.52% vs 94.32% | 差了 0.80 个百分点，看起来是提升。 |

## D. RunLedger Lab · 3 分钟横屏（16:9）

### 00:00–00:25 开场：一次运行的陷阱

- **画面**：`/` 选择页进入 `/lab`；总览页展示 digits 实验。
- **口播**：“工程里最容易犯的错，是把一次运行当成结论。RunLedger Lab 把基线和候选的真实重复运行放进同一张对照，先看差异是否大于波动。”

### 00:25–01:05 读一份真实实验：digits

- **操作**：在总览指出 MLP 32 / MLP 128 均值与种子数；切到「对比诊断」查看配对差值与信号噪声比；说明 128+L2 与 MLP 128 逐点相同、MLP 64×2 只有 1 个种子。
- **字幕**：0.80 个百分点 · 信号噪声比 ≈ 1.35 · 判读：差异仍需复测。
- **口播**：“差值是 0.80 个百分点，但配对差值波动约 0.60，所以比值只有约 1.35。基线三个种子都没收敛，这个对比还混入了训练是否充分的问题，不能解释为容量提升。”

### 01:05–01:40 读第二份实验：本地计时

- **操作**：切换到“本地高斯模糊性能计时”，展示 32 次记录、两实现中位数 18.85 ms / 10.77 ms，以及最大绝对误差 5.96e-08。
- **口播**：“计时实验有两次首调用和三十次预热。预热后的中位数差距明显，但它只代表本机这一次会话，不是跨机器结论；正确性上，两种实现的最大绝对误差约 6e-08。”

### 01:40–02:30 新建一个通用实验

- **操作**：点击「新建」→ 填“构建耗时对比”、单位“秒”、目标方向“越低越好”、目标记录数 8、不配对；提交后展示空状态；用「CSV模板」说明字段；现场录入 2–3 条演示测试值。
- **字幕**：基线 / 候选 · 数值指标 · 目标方向。
- **口播**：“内置实验只是演示。你可以用自己的指标建通用实验，录入真实重复运行值。系统不会生成看似合理的新数值。”

### 02:30–02:50 复测计划与证据

- **操作**：打开「复测计划」，展示按缺口排序；进入「记录与证据」展示批次、来源、环境与哈希；点击「导出证据JSON」。
- **口播**：“复测计划告诉你先补哪一组，而不是笼统地‘多跑几次’。证据 JSON 保留完整记录和版本事件，便于团队复核。”

### 02:50–03:00 收尾边界

- **画面**：回到总览，边界说明完整可见。
- **口播**：“信号噪声比不是 p 值，重复运行不等于随机试验，本机计时不代表跨机器性能。它不替你下结论。”

## F. 口播统一用词

| 可以说 | 不要说 |
| --- | --- |
| 差异仍需复测 | 显著提升 |
| 当前样本的均值 | 证明了效果 |
| 信号噪声比，用于复测排序 | p 值 / 显著性水平 |

| 观察性关联 | 因果关系 |
| 记录、证据与复测建议 | 健康建议 / 诊断结果 |
