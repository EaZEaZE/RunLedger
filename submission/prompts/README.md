## 提交前必须完成

- [ ] 至少 3 轮真实、可核对的原始 Prompt 导出。
- [ ] 至少 1 轮是真实问题复现与修复，包含实际错误、AI 响应、代码差异和修复后验证；不得为参赛伪造 Bug。
- [ ] 每轮保留用户原始输入，包括错别字、补充约束和后续追问，不润色成“完美 Prompt”。
- [ ] 每轮保留 AI 实际输出，或链接到同目录中的完整原始导出文件 / 截图。
- [ ] 记录真实日期时间、使用工具、可见模型名称、相关文件和真实命令结果。
- [ ] 若引用 Commit，必须填写公开仓库中真实存在且可访问的哈希；没有 Commit 就写“未提交”，不要编造。
- [ ] 删除密钥、令牌、个人敏感信息和无关隐私；脱敏处明确标记，不改变技术事实。

## 修 Bug 轮次的额外证据

真实修 Bug 轮次至少应能回答：

1. 问题在哪个真实版本、文件和操作路径中出现？
2. 修复前的实际错误文本、截图或可复现步骤是什么？
3. AI 提出了什么，哪些被采纳、哪些被拒绝？
4. 修改前后代码差异是什么？
5. 哪个真实命令或浏览器操作证明问题已修复？
6. 是否出现新问题或仍有未解决边界？

如果问题无法复现，应写“未复现，未修复”，不能把代码审查意见包装成已修 Bug。
